# FireFlow 無人実行ランナー（./fireflow-ai-run）

作成日：2026-08-15
目的：ユーザーがPCの前にいない時間帯（仕事日 6:00〜18:00）でも、FireFlowの通常ローカル開発が
承認待ちで止まらず最後まで進むようにする。重要判断だけを帰宅後の人間へ渡す。

このランナーはFireFlow本体の機能ではなく、開発基盤である。

---

## 1. 使い方（ユーザー）

```bash
cd ~/FireFlow/live-board-nextjs

# docs/current_task.md に書いた内容を実行
./fireflow-ai-run

# 任意のファイルを実行
./fireflow-ai-run path/to/task.md

# 文字列を直接渡す
./fireflow-ai-run "1101の時刻が表示されない原因を調べて直して"
```

終了後に見る場所は1つだけ。

```
logs/claude-runs/latest/report.md
```

## 2. 構成（3ファイルだけ）

| ファイル | 役割 |
|---|---|
| `fireflow-ai-run` | ランナー本体（bash）。`claude -p` を非対話で起動する |
| `fireflow-runner.settings.json` | 無人実行時の権限（allow / deny）。対話用の設定とは別 |
| `docs/current_task.md` | 既定のタスク置き場 |

ログは `logs/claude-runs/<日時>/` に残る（`.gitignore` 済み）。

## 3. 使っているClaude Code公式オプション

Claude Code 2.1.233 で実在を確認したものだけを使用している。

| オプション | 目的 |
|---|---|
| `-p` | 非対話実行（人間の承認ダイアログが構造的に発生しない） |
| `--output-format stream-json` ＋ `--verbose` | 実行過程を後から追える形で保存 |
| `--settings <file>` | ランナー専用の allow / deny |
| `--setting-sources user,project` | 対話用の `.claude/settings.local.json`(local) を読み込まない＝権限を固定する |
| `--permission-mode dontAsk` | 承認を求めない。許可外の操作は拒否され、実行は続く |
| `--disallowedTools` | 設定ファイルとは別に、CLI側でも最重要の破壊操作を塞ぐ二重の歯止め |
| `--max-budget-usd` | 任意。`FIREFLOW_RUN_BUDGET_USD=2 ./fireflow-ai-run` で有効 |

**`--max-turns` はこのバージョンのCLIに存在しない**ため使っていない（存在しないフラグは使わない方針）。
実行量の上限が必要な場合は `--max-budget-usd` を使う。

## 4. 自動で進む範囲

調査・コード検索・リポジトリ内のファイル編集と作成・
`test:unit` / `test:release` / `typecheck` / `build` / `lint`・
`npx tsx` でのテスト実行・dev server 起動・`curl http://localhost...`・ログ確認・修正・再テスト。

読み取り系のgit（status / diff / log / show / branch確認）も許可。

## 5. 実行させない操作

`git add` / `commit` / `push` / `checkout` / `switch` / `merge` / `rebase` / `reset` / `stash`、
GitHub(`gh`)、Vercel・deploy、`npm install` / `update` / `uninstall` / `publish`、
実API課金を伴うOCR（`ocr:benchmark` / `ocr:compare`）、Supabase・DB操作、
`.env`・APIキーの閲覧と変更、`rm -rf`、`sudo`、その他の不可逆・破壊的操作。

**対話時に「ask」だった操作は、無人実行では全て「deny」にしている。**
無人では誰も承認できないため、askのままにすると実行が止まるからである。
denyなら即座に拒否され、Claudeは他の安全な作業を続けられる。

拒否された操作は `logs/claude-runs/<日時>/denied.log` に機械的に記録され、
レポートの「無人実行では行えなかった操作」へ自動的に出る。
Claudeの報告漏れがあっても、実際に止められた操作は必ず残る。

## 6. 終了ステータス

| ステータス | 終了コード | 意味 |
|---|---|---|
| SUCCESS | 0 | 安全な範囲でタスク完了 |
| PARTIAL | 10 | 通常作業は進んだが、実LB確認等のユーザー操作が残る |
| BLOCKED | 20 | 重要操作が必要でこれ以上進めない |
| ERROR | 1 | ランナー自体の失敗（claude未検出・タスク未指定など） |

Claudeが最終行 `RUNNER_STATUS: ...` を出さずに終わった場合も、
実行結果の有無からランナー側でステータスを決めるため、判定が空になることはない。

## 7. レポートの形

Claudeは必ず次の4見出しで報告する。

```
【自動完了】
【テスト結果】
【残課題】
【帰宅後PC作業】
```

帰宅後に見るのは【帰宅後PC作業】だけでよい。

## 8. 秘密情報

ログ書き出し時に `sk-ant-...` / JWT / `*_KEY` `*_SECRET` `ACCESS_TOKEN` の形をマスクする。
`.env` の読み取りはランナー権限で禁止しているため、そもそもログへ入らない。

## 9. 検証結果（2026-08-15 実測）

Claude Code 2.1.233 / macOS で実際に確認した内容。

| 確認項目 | 結果 |
|---|---|
| 非対話実行（`claude -p`）で完走するか | **完走**（YES/NO待ち 0回、exit 0 / SUCCESS） |
| `git status` → コード検索 → `test:unit` → `typecheck` → `build` | すべて自動で実行、PASS |
| 禁止操作（`git commit --allow-empty`）に当たったとき | **即座に拒否され、実行は止まらず次の作業へ進んだ**（所要12秒） |
| 禁止操作が実際に実行されていないか | HEAD は `1bc3acd` のまま。コミットは作られていない |
| 秘密情報の読み取り（`cat *.env*`） | **拒否**（`permission_denials` に記録。`Bash(*.env*)` の deny が発火） |
| 拒否された操作の記録 | `denied.log` に自動記録され、レポートへ出る |
| FireFlow本体の変更 | なし（作業ツリー・HEAD ともに実行前後で同一） |

実行1回あたりの規模の目安：検証タスク（テスト＋typecheck＋build）で 61 イベント、数分。

補足：`--permission-mode dontAsk` は「承認を求めない」であって「何でも許す」ではない。
deny ルールは確実に効き、リポジトリ外への出力や `;` で繋いだ長い一行も拒否される。
（検証中に `npm run test:unit > /tmp/... ; grep ...` が拒否されたため、
ログ取得はパイプ `2>&1 | tail -N` を使うよう前置きへ明記した）

## 9.1 2026-08-15 実運用で判明したこと（タスク未記入で起動した回）

### (a) テンプレートのままでも起動していた → ガードを追加

`docs/current_task.md` が**テンプレートのまま**（見出し＋HTMLコメントの説明＋
`（ここに作業内容を書く）`）で `./fireflow-ai-run` が起動し、**1回分が空振り**した。
既存の判定は「空白を除いて空か」だけを見ており、説明文が入っているテンプレートは
中身が無くても通ってしまう（§6のERROR「タスク未指定」に到達しない）。

**修正**：`fireflow-ai-run` に、プレースホルダー `（ここに作業内容を書く）` が残っていたら
その場で `exit 1`（ERROR）にするガードを追加した。テンプレートは「置き換える」指示なので、
残っている＝まだ書かれていない、と一意に判定できる。見出しやコメントの解析はしない
（複雑な解析は無人実行側で実行検証できないため、誤って全タスクを止める危険がある）。

**このガードだけは実行検証できていない**（下記(c)）。確認用に
`test/trace/taskTemplateGuard.sh` を置いてあるので、手元で1回流せば確定する。

### (b) dev server 起動中に `npm run build` を流すと dev server が壊れる

両者が同じ `.next/` を使うため、build後のdev serverは `Cannot find module './xxx.js'` で
**500**を返すようになる（今回 `/api/v1/health` で実測）。コードの不具合ではなく、
dev serverを起動し直せば直る。実LB確認手順の §0 にも注意書きを追記した。
**無人実行でbuildを流した日は、ユーザーが実LB確認へ入る前にdev serverを再起動すること。**

### (c) 無人実行では bash / awk / ps / rm が実行できない

`fireflow-runner.settings.json` の許可範囲は「npm scripts と `npx tsx`」が中心のため、
`bash script.sh` / `awk` / `ps` / `rm`（単一ファイルでも）は拒否される。結果として、

- **シェルスクリプト（ランナー自身を含む）の挙動は無人実行で検証できない**
- 作業中に作ったファイルを無人実行側で消せない

この2点は仕様として受け入れる（許可を広げるとdeny設計が崩れるため）。
シェル側の変更は**必ず「帰宅後PC作業」へ回し、ユーザーが1回流して確定させる**運用とする。

## 10. 運用上の注意

- dev server は必ずバックグラウンドで起動するようプロンプトで指示している
  （前面起動は実行を止めるため）。
- `docs/current_task.md` は毎回上書きしてよい。実際に渡された内容は
  `logs/claude-runs/<日時>/task.txt` に残る。
