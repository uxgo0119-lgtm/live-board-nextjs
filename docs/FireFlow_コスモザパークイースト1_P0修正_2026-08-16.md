## P0-1 MASTER 39室

**修正内容**: 感知器個数表を取り込んだとき、`parseSensorCountSheet()` だけでなく
既存の `parseRoomRosterSheet()`（住戸一覧の正式Parser）にも同じWorkbookを通し、
部屋一覧が取れた場合は既存の
`toPropertyMasterIntake()` → `applyPropertyMasterIntakeToLb()` という
**既存の唯一のMASTER構築経路**へそのまま渡す。

- 新しいMASTERの正本は増やしていない（`toPropertyMasterIntake()` は元から
  `roomRosterResult` と `sensorCountResult` の同時受け取りに対応済み）
- Excel由来のため「MASTERはExcel由来を正本とする／OCRからMASTERを作らない」に適合
- 感知器個数が読めず部屋一覧だけ読めた場合（およびその逆）も、読めた分を捨てずに取り込む

**実ファイル結果**: MASTER室数 **39**、部屋番号は監査で確定した39室と完全一致、
階構成も一致（15F〜11F 各5室 / 10F・9F・8F・7F 各1室 / 6F〜2F 各2室）。

## P0-2 シート選択

**修正内容**: `SheetNames[0]`（1枚目）固定を廃止し、`pickIngestSheetResult()` で
全シートを既存Parserへ通し、**実際に値が取れたシート**を採用する。

- シート名のハードコードはしない（スコアで選ぶ）
  - 感知器個数: 個数の値（sa/tei/total のいずれか）を確定できた部屋数
  - 部屋一覧: 取得できた部屋番号の数
- ok:true が1枚も無い場合は、従来と同じ「1枚目の失敗結果」を返す
  （**1シート構成の帳票では、通る経路も結果もエラー文言も従来と完全に同一**）
- 感知器個数表・住戸一覧の**両分岐**に同じ形で適用

**実ファイル結果**: 3シート構成のうち3枚目「感知器個数」を採用（値のある部屋25室）。
1枚目・2枚目は従来どおり解析不能のまま。

## P0-3 差N・定M

**修正内容**: 既存の `roomOnlyPairRowsFormatParser`（部屋番号の行＋直下の自由記述セル）の
語句パターンを一般化した。**新しいフォーマットParserは追加していない。**

```
差動\s*(\d+)  →  差動?\s*(\d+)
定温\s*(\d+)  →  定温?\s*(\d+)
```

- 全角数字（差４・定２）は、部屋番号側と同じ既存 `zenkakuDigitsToHankaku()` で吸収
- 「差動式スポット型」のように直後が数字でない語句には一致しない
- `total = sa + tei` は既存の `sensorMasterFragmentFrom()` が従来どおり算出（値を捨てない）

**解析例**: `差4・定2` → sa:4 tei:2 total:6 ／ `差3・定2\n（右側：CL）` → sa:3 tei:2 total:5

**回帰**: 修正前バンドル（git HEAD）と修正後を、登録済み8フォーマットの代表グリッドと
実ファイル全シートで差分比較し、**「差N・定M」以外は判定結果・抽出値とも完全一致**を確認した。

## 保存・復元

`extendSensorMasterFromEntries()` の保存条件が「新規の部屋が増えた場合」だけだったため、
既存の部屋へ個数を補完しただけの取込（先に部屋一覧を読んでから感知器個数表を読む、
同じ資料を再取込する等）では保存が走らず、再読込で値が消えていた。

- `mergeSensorMasterField()` が「実際に書き換えたか」を返すようにし、
  値が変わった場合も `persistCurrentProperty()` を呼ぶ（新しい保存経路は作っていない）
- 同じ値の再取込では保存しない（無駄な書き込みを増やさない）
- 併せて、値が1件も読めなかった部屋を「感知器個数を追加した」件数に数えないよう修正
  （実際より多い件数を成功として表示していた＝件数の捏造）

**実ファイル結果**: RAW → 正式内部データ → SENSOR_MASTER → 保存 → 復元 → LB表示用データ を
全25室について機械的に比較し、**不一致0**。再読込後も `state:'confirmed'` で値が残る。
