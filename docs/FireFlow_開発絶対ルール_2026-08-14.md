# FireFlow 開発 絶対ルール（2026-08-14制定）

このルールはLive Board / Report Flow / FireFlowの全開発に適用する。
新しいClaude Codeセッション・開発フェーズでも必ず引き継ぐ。

## 1. 無駄な作業をさせない

- ユーザーにターミナル操作・確認・再テストを依頼する前に、「本当にその作業が次の判断に必要か」を確認する
- すでに確認済みの内容を、言い方を変えて再確認させない
- 1つのコマンドでまとめられる作業を、複数回に分けてユーザーへ依頼しない
- Claude Code側で自動実行できる作業は、原則Claude Code側で行う
- ユーザーにしかできない操作は、最後にまとめて最小回数だけ依頼する

## 2. 同じことを何度も繰り返さない

- 確認済みの事実は「確定事実」として保持する
- 新しい証拠が出ない限り、同じ調査を最初からやり直さない
- 同じ不具合に対して「推測修正→テスト→推測修正」を繰り返さない
- 1回目の修正で直らなかった場合は、次の修正前に必ず「実データがどこで変化したか」を特定する
- 同じ物件・同じ論点を延々検証しない

## 3. Live Boardの実装を最後まで確認してから先へ進む

- コードがあるだけでは未完成
- unit test PASSだけでは未完成
- build PASSだけでは未完成
- Claude上で正しいだけでは未完成
- 最終判断基準は【実際のLive Boardでユーザーが正常に使えるか】
- 実ファイル→実API→実データ変換→LB内部保存→LB描画→ユーザーが見る画面まで通して確認する

## 4. 「点」ではなく「線」で設計する

必ず、

入力
→解析
→正規化
→業務ルール
→保存
→復元
→描画
→次工程

まで一本の線として設計する。

途中だけ完成しても完成扱いしない。

## 5. 正本データを明確にする

- 同じ情報を複数の場所で別形式に持たない
- どのデータが正本か必ず決める
- OCR結果、normalize結果、STAMP_DATA、localStorage、描画用データが別々の意味を持つ状態を避ける
- 正本確定後は後段で再解釈しない
- LBは原則、確定済みデータを保存・復元・表示する

## 6. 過去の決定事項を必ず反映する

恒久ルール：

- MASTERはExcel由来を正本とする
- OCRからMASTERを再生成しない
- 曖昧な値を勝手に確定しない
- FireFlow辞書を正式パイプライン内で使う
- Legacy/New OCRの違いをユーザーへ見せない
- 資料読み込み入口は1つ
- 50〜60代でも説明なしで使えるUI
- 紙より簡単でなければ意味がない
- 実LB確認前にGOを出さない

## 7. 過去結果と新結果が矛盾したら先に止まる

- 以前PASSした内容と現在の実LB結果が違う場合、新しい修正を始める前に原因を確認する
- GitHub、Cowork、Macローカル、Vercel、localhostを混同しない
- FireFlow実装作業ではMacローカルClaude Codeを正本環境として優先する
- Coworkの合成入力を実LB E2Eの代わりにしない

## 8. 推測で原因確定しない

「たぶんここ」で修正しない。

画像
→ OCR raw
→ FireFlow辞書
→ normalize
→ LB変換
→ 保存
→ 復元
→ 描画

のどこで値が最初に変化したか確認して原因を確定する。

原因確定前にコードを変更しない。

## 9. 修正は最小限

- 原因が確定した場所だけ修正
- 無関係なリファクタリング禁止
- 別機能のついで修正禁止
- Ground Truthを書き換えてテストを通すだけの対応禁止
- 特定物件・特定部屋番号のハードコード禁止
- 今後の物件にも通用する一般ルールとして修正する

## 10. 完了条件を先に決める

- 作業開始時に「何ができたら終了か」を決める
- 終了条件を満たしたら一度止める
- 追加改善は別タスクへ分離する
- 1物件・1機能を無限に磨き続けない

## 11. GOを段階分けする

LOCAL_GO：

- コード実装済み
- 必要な自動テストPASS
- 実データPASS
- Ground Truth確認
- 実Live Board UI確認
- 保存・再読込確認
- MASTER維持確認

RELEASE_GO：

- LOCAL_GO達成済み
- commit済み
- push済み
- Vercel最新deploy確認
- 本番URL実E2E確認

途中状態では、
CODE_ONLY
UI_UNVERIFIED
DEPLOY_PENDING
など正確に表現する。

## 12. ユーザーの時間を最優先する

- 開発作業そのものをユーザーの負担にしない
- 同じスクショ、同じコマンド、同じ説明、同じテストを何度も求めない
- ユーザーにしかできない確認は1回で必要情報が取れるよう設計する

## 13. ターミナル依存を減らす

Phase 8 Dev Consoleへ順次移行する。

最終的に、

- LB起動
- テスト
- Git確認
- E2E
- ログ確認

をボタン操作中心にする。

ただし新捺印表パイプライン完成前にPhase 8へ着手しない。

## 14. Claude Codeの承認要求は重要操作に限定する（2026-08-15追加）

ユーザーはプログラマーではない。開発のたびにYES/NOを何十回も押させる運用は禁止する。

- 通常の読み取り・検索・リポジトリ内編集・テスト・typecheck・build・dev server起動・localhost確認で、ユーザーへ何度も承認を要求しない
- FireFlow用のpermissions設定（`.claude/settings.local.json`）を尊重し、そこで許可済みの操作は確認せずに実行する
- 同じ種類のYES/NOを繰り返さない。細切れのコマンドで承認を積み上げず、安全な操作はまとめて実行する
- 通常開発では承認0回を基本目標とする
- ユーザーの時間を、開発作業の承認待ちで消費させない
- ただし次は必ず確認を残す：commit / push / deploy / 破壊的Git操作（reset --hard・clean・branch削除等）/ 大量削除 / 依存パッケージの追加・更新 / 秘密情報（.env・APIキー）の閲覧・変更 / 本番データ・DBの変更 / 外部サービスへの書き込み / 不可逆操作
- force pushは禁止（設定上もdenyとする）
- 「全Bash許可」「全コマンド許可」のような万能許可で承認を減らさない。必要な範囲だけを許可する
- permissions設定に個人環境固有の情報（絶対パス等）が含まれる場合はGit管理しない。運用ルール自体はこのdocsを正本とする
- localhost確認は `curl -s http://localhost...` の形で書く（許可済みの形のため確認が出ない）

### Permission方針（2026-08-15確定・恒久）

`.claude/settings.local.json` を正本の設定場所とし、次の3段構えを維持する。

- **通常のローカル開発は auto**（`permissions.defaultMode: "auto"`）
  調査・コード検索・ファイル編集・実装・テスト・typecheck・build・dev server・localhost確認・ログ確認・修正・再テストは、**YES/NO確認0回**を基本とする。
  allowルールを大量に追加して穴を塞ぐ方式には戻さない（Bashの許可はコマンド文字列の前方一致であり、パイプ・リダイレクト・ヒアドキュメント・複合コマンドを列挙で覆いきれないことが2026-08-15の調査で確定しているため）。
- **重要操作は ask**（確認を必ず残す）
  git add / commit / push / checkout / switch / merge / rebase / restore / revert、GitHub（gh）、Vercel・deploy、npm install / update / uninstall / publish、実API課金を伴うOCR（ocr:benchmark / ocr:compare）、Supabase・DBへの直接操作、`.env`・APIキー関連、その他外部へ影響する操作。
- **破壊操作は deny**（実行させない）
  force push（-f / --force / --force-with-lease）、reset --hard、git clean、checkout -f、branch -D/-d、filter-branch、rm -rf、sudo、chmod 777、mkfs、dd。

設定はプロジェクトスコープのため、この作業ディレクトリで起動する以降の全セッションへ自動適用される。
ただし**セッション途中で作成・変更した設定はそのセッションには反映されない**（設定監視はセッション開始時点で存在したディレクトリのみが対象）。変更後は必ずClaude Codeを再起動する。

## 15. 最優先原則

速さより「一発で正しい方向へ進むこと」。

ただし安全確認を理由に同じ確認を繰り返さない。

調査したら決める。
決めたら実装する。
実装したら実LBで確認する。
確認できたら次へ進む。

このサイクルを崩さない。
